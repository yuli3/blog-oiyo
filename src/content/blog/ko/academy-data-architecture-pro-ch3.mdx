## 요건은 모델링 전의 약속입니다

데이터 요건은 사용자가 원하는 화면 목록이 아니라, 업무가 어떤 사실을 기록하고 어떤 기준으로 조회·판단하려는지 정리한 요구입니다. DAP 수준에서는 요구사항을 곧바로 테이블로 옮기지 않고, 업무 규칙, 데이터 발생 시점, 책임 부서, 품질 기준까지 함께 봐야 합니다. 이 단계가 흐리면 이후 모델링과 표준화가 모두 흔들립니다.

### 표준화의 기본 단위

| 항목 | 의미 |
|---|---|
| 표준 용어 | 조직 안에서 같은 의미로 쓰는 업무 단어 |
| 도메인 | 값의 형식, 길이, 허용 범위 기준 |
| 코드 | 반복적으로 쓰는 분류값의 체계 |
| 명명 규칙 | 테이블·컬럼 이름을 일관되게 만드는 규칙 |

표준은 개발자를 귀찮게 하는 문서가 아닙니다. 같은 고객을 한 시스템은 “고객”, 다른 시스템은 “회원”, 또 다른 시스템은 “거래처”로 부르면 통합과 분석이 어려워집니다. 표준 용어는 의미를 맞추고, 도메인은 값의 품질을 맞추며, 코드는 업무 분류를 통제합니다.

## 실전 판단법

문제에서 “중복 입력”, “부서별 다른 명칭”, “분석 기준 불일치”가 보이면 표준화 관점으로 접근하세요. 반대로 “필요한 정보가 누락됨”, “업무 규칙이 모델에 반영되지 않음”은 요건 분석의 문제일 가능성이 큽니다.

## 핵심 요약

- 데이터 요건은 업무 사실, 규칙, 품질 기준을 데이터 관점으로 정리한 일입니다.
- 표준 용어, 도메인, 코드, 명명 규칙은 데이터 정합성의 기초입니다.
- DAP에서는 요건과 표준을 모델링 이전의 핵심 통제 장치로 이해해야 합니다.
