## 프로젝트 종료의 중요성

많은 팀이 프로젝트 종료를 소홀히 합니다. 그러나 제대로 된 종료는 조직의 미래 역량을 쌓는 핵심 과정입니다.

```
종료가 부실할 때의 비용:
→ 고객이 공식 수락 안 함 → 분쟁 발생
→ 교훈 미문서화 → 같은 실수 반복
→ 조달 계약 미종료 → 법적 분쟁
→ 팀원 공헌 미인정 → 사기 저하
```

---

## 종료 유형

```
정상 종료:
→ 모든 인도물 완성·수락
→ 공식 종료 문서 서명

조기 종료 (Early Termination):
→ 프로젝트 취소 결정
원인: 전략 변경, 예산 소진, 환경 변화
→ 취소도 공식 종료 프로세스 필요

단계별 종료 (Phase-Gate):
→ 각 단계 종료 시 다음 단계 진행 여부 결정
→ Go/No-Go 결정
```

---

## 공식 종료 프로세스

```
1. 인도물 최종 검수
   → 고객 수락 기준 달성 확인
   → 잔여 결함 처리 or 다음 단계 이관
   → 공식 수락서 (Acceptance Document) 서명

2. 조달 계약 종료
   → 공급업체 최종 인도물 검수
   → 미결 클레임 처리
   → 최종 지불 승인
   → 계약 종료 확인서 발행

3. 행정 종료
   → 프로젝트 기록 보관 (규정 준수)
   → 프로젝트 팀 해산
   → 자원 반환 (인력·장비·예산)
   → 최종 보고서 작성
```

## 교훈 (Lessons Learned) 관리

### 교훈이 중요한 이유

```
동일 실수 반복 = 조직 비용 낭비
→ 업계 통계: 프로젝트의 75%가 이전 실패와 유사한 문제를 반복

교훈 저장소의 가치:
→ 미래 PM의 시간 절약
→ 리스크 대응 전략 재사용
→ 베스트 프랙티스 조직화
```

### 효과적인 교훈 회의

```
준비:
→ 모든 팀원에게 사전 설문 (익명 가능)
→ 데이터 기반 준비 (일정·비용·품질 편차)

진행:
→ 비난 금지 (No-Blame Culture)
→ "무엇이" 일어났는가 (Why 5회 반복)
→ 잘 된 것 먼저 → 개선점

문서화:
→ 상황 (What happened?)
→ 영향 (Impact)
→ 원인 (Root Cause)
→ 재발 방지 권고 (Recommendation)
```

### 교훈 문서 예시

```
상황: 핵심 개발자 2명이 스프린트 3주차에 이직
영향: 일정 2주 지연, 비용 500만 원 추가
원인: 인력 리스크 미식별, 대체 인력 계획 없음
권고: 핵심 자원에 대한 백업 계획 수립 의무화
      계약 종료 6주 전 이직 의향 체크 추가
```

## 최종 보고서 구성

```
1. 프로젝트 개요
   → 목적, 범위, 기간, 예산

2. 성과 요약
   → 목표 달성 여부 (범위·일정·비용·품질)
   → 주요 인도물 현황

3. 성과 측정 비교
   → 계획 vs 실제 (일정·비용 편차 분석)
   → EVM 지표 (SPI, CPI)

4. 주요 문제 및 해결 방법

5. 교훈 요약

6. 권고사항 (미래 유사 프로젝트용)

7. 스폰서 서명
```

## 팀 해산과 성과 인정

```
성과 인정의 중요성:
→ 팀원 동기 부여
→ 조직 내 긍정적 문화 형성
→ 유사 프로젝트 자원 확보 용이성

방법:
→ 개인별 공헌 문서화
→ 상급 관리자에게 성과 보고
→ 종료 기념 행사 (Kick-down 파티)
→ 팀원 성장 기록 → 이력 참조 자료

자원 반환:
→ 팀원 부서 복귀 통보
→ 임시 인력 계약 종료
→ 장비·소프트웨어 라이선스 반환
```

## 핵심 암기 포인트

*프로젝트 종료 = 인도물 수락 + 계약 종료 + 행정 종료*
*교훈 문서화: 상황 → 영향 → 원인 → 권고 (No-Blame)*
*조기 종료도 공식 종료 프로세스 적용 필수*
*최종 보고서: 성과 요약 + 편차 분석 + 교훈 + 권고사항*
