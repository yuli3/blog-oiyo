## 운영은 데이터의 수명주기를 관리합니다

데이터 운영은 생성, 변경, 저장, 이관, 보관, 폐기까지 이어지는 수명주기를 관리하는 일입니다. DAP 관점에서는 운영 절차가 모델과 표준을 유지하는지, 변경이 발생했을 때 영향 분석이 가능한지, 장애나 품질 문제가 생겼을 때 복구와 책임 체계가 준비되어 있는지를 봐야 합니다.

### 운영·보안 점검표

| 항목 | 확인 질문 |
|---|---|
| 접근 통제 | 누가 어떤 데이터에 접근할 수 있는가 |
| 변경 관리 | 구조 변경의 승인과 영향 분석이 있는가 |
| 이력 관리 | 생성·수정·삭제 기록을 추적할 수 있는가 |
| 보호 조치 | 민감 정보와 개인정보가 적절히 보호되는가 |

보안은 별도 부서의 일로만 분리해서 보면 안 됩니다. 데이터 모델에 민감 정보가 어디에 있는지 식별되어야 접근 권한, 암호화, 마스킹, 로그 관리가 가능해집니다. 개인정보와 관련된 법규·고시·기관 지침은 변경될 수 있으므로 실제 적용 시에는 시행처 공식 홈페이지와 관계 기관 공지를 확인해야 합니다. 확인일: 2026-06.

## 시험식 사고

운영 문제는 “누가, 언제, 어떤 기준으로”를 묻는 경우가 많습니다. 데이터 보안 문제는 보호 대상 식별, 권한 최소화, 접근 기록, 외부 제공 통제처럼 관리 절차와 기술 조치를 함께 연결하세요.

## 핵심 요약

- 데이터 운영은 수명주기, 변경, 복구, 책임 체계를 관리합니다.
- 보안은 모델의 민감 정보 식별에서 시작해 접근 통제로 이어집니다.
- 법규·기관 지침은 최신 공식 공지를 확인해야 하며 단정하면 안 됩니다.
