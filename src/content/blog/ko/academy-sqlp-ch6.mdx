## 튜닝은 추측이 아니라 진단입니다

실전 튜닝은 “느리다”는 감상에서 시작하지 않습니다. 어떤 SQL이 자주, 오래, 어떤 자원을 쓰는지 확인합니다. 그다음 실행계획과 실제 건수로 병목을 좁힙니다.

### 튜닝 절차

| 단계 | 할 일 | 산출물 |
|------|-------|--------|
| 1 | 문제 SQL 식별 | 대상 쿼리 |
| 2 | 실행계획 확인 | 접근·조인 방식 |
| 3 | 데이터량 비교 | 예상/실제 건수 |
| 4 | 개선안 적용 | 인덱스, SQL 재작성 |

SQL 재작성은 조건을 명확히 하고 불필요한 함수, 중복 조인, 과도한 정렬을 줄이는 방향입니다. 결과 의미가 바뀌면 실패이므로 반환 행 수를 비교하세요.

## 핵심 요약

SQL 튜닝은 대상 식별, 실행계획 분석, 데이터량 검증, 개선안 적용, 결과 검증의 순서입니다.

다음 장에서는 성능과 무결성에 큰 영향을 주는 락과 트랜잭션을 다룹니다.
