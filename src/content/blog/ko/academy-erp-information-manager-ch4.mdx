## 실무 회계는 입력 후 검증까지다

ERP 회계 모듈 실무는 전표를 입력하는 데서 끝나지 않습니다. 매출, 매입, 비용, 입금, 지급, 결산 조정이 각각 어떤 장부와 보고서에 영향을 주는지 확인해야 합니다. 시험형 문제도 단순 분개보다 입력 오류, 조회 조건, 보고서 해석을 함께 묻는 방식으로 준비하는 편이 좋습니다.

### 주요 업무 흐름

| 업무 | 확인 포인트 |
|---|---|
| 매출 입력 | 거래처, 공급가액, 부가세, 채권 잔액 |
| 매입 입력 | 매입처, 세금계산서, 지급 예정액 |
| 비용 처리 | 비용 계정, 부서, 증빙 유형 |
| 결산 | 감가상각, 선급·미지급, 재고·손익 마감 |

실무 입력 문제를 풀 때는 "거래 사실 -> 증빙 -> 전표 -> 잔액 -> 보고서" 순서로 말할 수 있어야 합니다. 예를 들어 비품을 현금으로 구입했다면 자산 인식 여부, 부가세 처리, 지급 수단, 감가상각 대상 여부까지 이어집니다. 매출채권 회수라면 매출을 다시 잡는 것이 아니라 채권 잔액을 줄이는 입력인지 확인해야 합니다.

### 보고서 검증

입력 후에는 계정별원장, 거래처원장, 시산표, 손익계산서 같은 보고서를 조회합니다. 보고서는 정답을 보여주는 화면이 아니라 입력의 결과를 검증하는 도구입니다.

조회 결과가 어색하면 전표 날짜, 계정과목, 거래처, 세액 구분을 거꾸로 추적하세요. 실무형 문제는 이 역추적 능력을 확인하는 방식으로 출제될 수 있습니다.

## 핵심 요약

ERP 회계 실무는 입력과 조회가 한 세트입니다. 거래 성격을 분개로 판단하고, 전표 입력 후 잔액과 보고서까지 확인해야 합니다. 다음 장에서는 인사·급여 모듈의 기본 흐름을 배웁니다.
