## 설계는 요구사항을 구조로 바꾸는 일입니다

소프트웨어 설계는 사용자가 원하는 기능을 개발자가 구현할 수 있는 구조로 바꾸는 단계입니다. 시험에서는 요구사항 분석, UML, 화면 설계, 아키텍처, 모듈화 개념이 자주 연결됩니다. 세부 출제 기준은 바뀔 수 있으므로 [Q-net](https://www.q-net.or.kr)과 시행처 공식 홈페이지의 공고를 확인하세요. 확인일: 2026-06.

### 설계 단원 핵심

| 주제 | 학습 포인트 |
|---|---|
| 요구사항 | 기능·비기능 요구사항 구분 |
| UML | 유스케이스, 클래스, 시퀀스 흐름 |
| 모듈화 | 응집도는 높게, 결합도는 낮게 |
| 아키텍처 | 계층화, MVC, 클라이언트-서버 |

강의식으로 보면 설계 문제는 “무엇을 만들 것인가”와 “어떻게 나눌 것인가”를 묻습니다. UML 기호를 외울 때도 그림 자체보다 어떤 요구사항을 표현하는지 생각해야 합니다. 응집도와 결합도는 실기에서도 설명형 답안으로 나오기 쉬우니 짧은 문장으로 정리해 두세요.

## 핵심 요약

- 설계는 요구사항을 구현 가능한 구조로 바꾸는 과정입니다.
- UML은 요구사항과 객체 관계를 표현하는 도구로 이해합니다.
- 공식 출제 기준은 Q-net과 시행처 공식 홈페이지에서 확인합니다.

다음 장에서는 소프트웨어 개발 단계의 구현, 테스트, 형상관리를 정리합니다.
