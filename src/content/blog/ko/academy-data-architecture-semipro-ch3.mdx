## 요구사항은 모델의 출발점입니다

데이터 요구사항 분석은 사용자가 원하는 화면 목록을 받는 일이 아닙니다. 업무에서 어떤 사실을 기록해야 하는지, 어떤 기준으로 조회하고 집계해야 하는지, 어떤 품질 조건을 지켜야 하는지 찾는 과정입니다. 요구사항이 흐리면 모델도 흐려지고, 나중에는 컬럼 추가와 예외 처리로 시스템이 복잡해집니다.

### 분석 대상

| 대상 | 확인할 내용 |
|---|---|
| 업무 규칙 | 반드시 지켜야 하는 조건과 예외 |
| 정보 요구 | 보고서, 조회, 분석에 필요한 데이터 |
| 데이터 흐름 | 생성, 변경, 참조, 폐기 경로 |
| 품질 조건 | 정확성, 중복, 누락, 최신성 |
| 제약 조건 | 보안, 권한, 보존 기간 |

예를 들어 “회원 등급별 혜택을 보고 싶다”는 요구는 회원, 등급, 혜택, 적용 기간, 변경 이력이라는 데이터 요소로 풀어야 합니다. 문장을 엔터티와 속성, 관계 후보로 바꾸는 훈련이 요구사항 분석의 핵심입니다.

## 인터뷰와 산출물

요구사항은 인터뷰, 문서 분석, 현행 시스템 분석, 워크숍으로 수집할 수 있습니다. 중요한 것은 들은 말을 그대로 저장하는 것이 아니라 검증 가능한 산출물로 정리하는 것입니다. 요구사항 목록, 업무 규칙 표, 데이터 흐름, 용어 후보, 이슈 목록을 남기면 모델링 단계에서 추적이 쉬워집니다.

## 핵심 요약

- 데이터 요구사항은 화면이 아니라 업무 사실과 정보 요구를 찾는 과정입니다.
- 문장을 엔터티, 속성, 관계 후보로 바꾸는 연습이 필요합니다.
- 요구사항 산출물은 이후 표준화와 모델링의 근거가 됩니다.

다음 장에서는 용어, 도메인, 코드, 명명 규칙을 포함한 데이터 표준화를 정리합니다.
