## 통합 관리란 무엇인가

프로젝트 통합 관리는 프로젝트의 모든 프로세스와 지식 영역(범위·일정·비용·품질·리스크 등)을 조율하고 통합하는 역할입니다.

```
핵심 역할:
범위 변경 → 일정과 비용에 어떤 영향?
리스크 발생 → 품질과 이해관계자에게 어떤 영향?
→ 전체 그림을 보는 PM의 가장 중요한 역량
```

---

## 프로젝트 헌장 (Project Charter)

### 헌장의 역할

```
프로젝트 헌장 = 프로젝트의 출생 증명서

포함 내용:
- 프로젝트 목적과 정당성
- 측정 가능한 목표 및 성공 기준
- 고수준 요구사항
- 고수준 리스크
- 예산 요약
- 마일스톤 일정
- PM 권한과 책임
- 스폰서 서명

→ 스폰서 서명 = 공식 승인 = 자원 사용 권한
```

### 헌장이 없을 때의 문제

```
- PM 권한 불명확 → 팀원 협조 어려움
- 범위 기준 없음 → 범위 크리프 무한 확대
- 성공 기준 없음 → 종료 시점 판단 불가
```

---

## 프로젝트 관리 계획서 (PMP)

```
모든 보조 계획서를 통합하는 최상위 문서:

범위 관리 계획 + 일정 관리 계획 + 비용 관리 계획
+ 품질 관리 계획 + 자원 관리 계획 + 커뮤니케이션 계획
+ 리스크 관리 계획 + 조달 관리 계획
= 프로젝트 관리 계획서

→ 기준선 (Baseline) 설정: 범위·일정·비용 기준선
→ 이후 모든 변경의 비교 대상
```

## 통합 변경 통제

### 변경 통제 프로세스

```
변경 요청 접수
    ↓
변경 요청서 작성 (공식 문서화)
    ↓
영향 분석 (범위·일정·비용·품질·리스크)
    ↓
변경 통제 위원회 (CCB) 검토 → 승인/거부/보류
    ↓
승인 시: 프로젝트 계획 업데이트 + 이해관계자 통보
거부 시: 변경 요청자에게 이유 통보
```

### 변경 통제 핵심 원칙

```
모든 변경은 문서화해야 한다:
→ 구두 변경 요청은 없음 (Non-existent)
→ "작은 변경"도 영향 분석 필수

기준선 보호:
→ 승인된 변경만 기준선 업데이트 가능
→ 무단 범위 변경 = 범위 크리프
```

## 프로젝트 작업 지시 및 관리

```
실행 단계의 핵심 활동:

작업 지시:
- WBS 작업 패키지 단위 배분
- 자원 할당 및 지시

진행 관리:
- 실제 진행 vs 계획 비교
- 편차 분석 → 시정 조치

결과물 품질 확인:
- 검수 기준 사전 정의
- 인도물 완성도 검토
```

---

## 프로젝트 지식 관리

```
명시적 지식: 문서화된 정보
→ 프로세스 문서, 교훈 저장소, 기술 명세서

암묵적 지식: 사람 머릿속 전문성
→ 인터뷰, 워크숍, 멘토링으로 공유

교훈 관리:
→ 프로젝트 종료 시 반드시 문서화
→ 조직 프로세스 자산으로 저장
→ 미래 프로젝트에서 재사용
```

---

## 통합 관리의 핵심 도구

```
회의 관리:
- 킥오프 회의: 팀 결성, 목표 공유
- 상태 회의: 진행 확인, 장애물 제거
- 교훈 회의: 종료 시 성공·실패 분석

프로젝트 정보 시스템 (PMIS):
- Jira, MS Project, Asana 등
- 계획·실행·보고 통합 플랫폼
```

## 핵심 암기 포인트

*프로젝트 헌장 = 공식 승인 + PM 권한 부여 (스폰서 서명)*
*모든 변경은 반드시 문서화 → CCB 검토 → 기준선 업데이트*
*통합 관리 = 전체 지식 영역의 조율·연결*
*교훈 문서화 = 조직 자산으로 미래 프로젝트에 재활용*
