## 개발은 코드만 쓰는 단계가 아닙니다

SW 개발 단원은 구현, 테스트, 통합, 형상관리, 배포의 흐름을 다룹니다. 코드 작성 자체보다 개발 산출물이 어떻게 관리되고, 결함이 어떻게 발견되며, 변경 이력이 어떻게 통제되는지 보는 과목입니다. 세부 범위와 시험 형식은 공식 공고 기준으로 [Q-net](https://www.q-net.or.kr)과 시행처 공식 홈페이지에서 확인하세요. 확인일: 2026-06.

### 개발 단계별 포인트

| 단계 | 확인할 내용 |
|---|---|
| 구현 | 코딩 표준, 모듈, 예외 처리 |
| 테스트 | 단위, 통합, 시스템, 인수 테스트 |
| 형상관리 | 버전, 변경 요청, 기준선 |
| 배포 | 릴리스, 롤백, 운영 반영 |

시험에서는 테스트 종류를 단순 나열하기보다 목적을 구분해야 합니다. 단위 테스트는 작은 모듈, 통합 테스트는 모듈 사이 연결, 시스템 테스트는 전체 기능, 인수 테스트는 사용자 요구 충족 여부를 확인합니다. 형상관리는 실무 감각이 필요한 단원이므로 “누가, 언제, 무엇을 바꾸었는가”를 추적하는 장치로 기억하세요.

## 핵심 요약

- SW 개발은 구현, 테스트, 형상관리, 배포가 함께 움직입니다.
- 테스트는 단계별 목적을 구분해야 합니다.
- 세부 시험 정보는 Q-net과 시행처 공식 홈페이지에서 확인합니다.
