## 모델링은 업무를 구조로 바꾸는 일입니다

데이터 모델링은 업무에서 다루는 사실을 엔터티, 속성, 관계로 표현하는 과정입니다. 개념 모델은 큰 업무 개체와 관계를 잡고, 논리 모델은 식별자와 속성, 관계를 정교하게 정리하며, 물리 모델은 실제 데이터베이스 구현 조건을 반영합니다. 세 단계는 따로 외우기보다 상세화의 흐름으로 이해하세요.

### 모델 단계

| 단계 | 핵심 산출물 |
|---|---|
| 개념 모델 | 주요 엔터티와 업무 관계 |
| 논리 모델 | 속성, 식별자, 정규화, 관계 상세 |
| 물리 모델 | 테이블, 컬럼, 인덱스, 제약조건 |
| 검토 | 중복, 누락, 업무 규칙 반영 여부 |

엔터티는 관리해야 할 대상이고, 속성은 그 대상이 가진 정보입니다. 관계는 엔터티 사이의 업무적 연결입니다. 예를 들어 주문은 고객과 상품 사이의 거래 사실을 표현하고, 주문일자와 수량은 속성이 됩니다.

## 정규화와 식별자

논리 모델링에서는 정규화로 중복과 이상 현상을 줄입니다. 식별자는 데이터를 유일하게 구분하는 기준이므로 업무 식별자와 대체 식별자의 차이를 알아야 합니다. 물리 모델링에서는 성능과 운영 조건 때문에 인덱스, 파티션, 반정규화 같은 선택이 나올 수 있지만, 기본 논리 구조가 무너지면 안 됩니다.

## 핵심 요약

- 데이터 모델링은 업무 사실을 엔터티, 속성, 관계로 구조화하는 과정입니다.
- 개념, 논리, 물리 모델은 상세화와 구현 반영의 단계입니다.
- 정규화와 식별자는 모델 품질을 좌우하는 핵심 개념입니다.
