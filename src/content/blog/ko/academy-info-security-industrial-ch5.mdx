## 암호는 목적부터 구분합니다

암호 단원은 용어가 비슷해서 헷갈리기 쉽습니다. 대칭키는 빠른 암호화, 공개키는 키 교환과 전자서명, 해시는 무결성 확인, 인증은 사용자의 신원 확인이라는 식으로 목적을 먼저 나누세요. 구체적인 알고리즘 출제 범위는 회차별 기준에 따라 달라질 수 있으므로 [Q-net](https://www.q-net.or.kr)과 시행처 공식 홈페이지 공고를 확인합니다. 확인일: 2026-06.

### 기본 구분표

| 개념 | 핵심 기능 |
|---|---|
| 대칭키 암호 | 같은 키로 암호화와 복호화 수행 |
| 공개키 암호 | 공개키와 개인키를 분리해 사용 |
| 해시 | 원문을 고정 길이 값으로 변환 |
| 전자서명 | 무결성, 인증, 부인방지 확인 |
| 인증 | 지식, 소유, 생체 등으로 신원 확인 |

시험에서는 “암호화했다”라는 표현만 보고 답을 고르면 위험합니다. 기밀성이 필요한지, 위변조 확인이 필요한지, 보낸 사람 확인이 필요한지에 따라 답이 달라집니다. 문제 문장에서 요구하는 보안 속성을 먼저 표시하세요.

## 핵심 요약

- 암호 단원은 기밀성, 무결성, 인증, 부인방지를 구분해야 합니다.
- 해시는 암호화가 아니라 무결성 확인에 가깝게 이해합니다.
- 세부 알고리즘 범위는 공식 공고에서 확인해야 합니다.
