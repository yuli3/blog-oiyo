## 삼중 제약 (Triple Constraint)

모든 프로젝트는 세 가지 제약이 서로 영향을 줍니다:

```
         범위(Scope)
           △
          / \
         /   \
        /     \
일정 ──────────── 비용
(Schedule)      (Cost)
```

하나를 변경하면 다른 둘에 영향. PM은 이 균형을 관리합니다.

---

## 범위 관리

### WBS (Work Breakdown Structure)
프로젝트 전체 작업을 계층적으로 분해한 구조.

```
프로젝트
├── 1. 기획
│   ├── 1.1 요구사항 수집
│   └── 1.2 범위 정의
├── 2. 개발
│   ├── 2.1 백엔드
│   └── 2.2 프론트엔드
└── 3. 테스트
    └── 3.1 QA
```

**WBS 작업 패키지**: 최하위 요소. 일정·비용 추정 가능 단위.

### 범위 크리프 (Scope Creep)

공식 승인 없이 범위가 점진적으로 확장되는 현상. 프로젝트 실패의 주요 원인.

**방지 방법**: 공식 변경 통제 프로세스, 승인된 범위기준선 관리, 이해관계자와 명확한 범위 소통.

<Callout type="tip">
**시험 핵심**: 이해관계자가 새로운 기능을 요청하면? → 변경 통제 프로세스를 따르고 공식 변경 요청(Change Request)을 제출하도록 안내합니다. 비공식 요청을 바로 수락하면 안 됩니다.
</Callout>

## 일정 관리

### 임계 경로법 (Critical Path Method, CPM)

프로젝트의 최단 완료 기간과 활동들의 여유 시간을 계산하는 방법.

**임계 경로**: 가장 긴 경로 = 프로젝트 최소 기간

```
활동 A (3일) → 활동 C (2일)
                              → 종료 (총 8일 = 임계 경로)
활동 B (5일) → 활동 D (3일)
```

임계 경로: B → D (8일)
A → C는 5일 → 여유 3일 (Total Float = 3일)

**Float(여유 시간)**: 일정 지연 없이 활동을 늦출 수 있는 기간.
- 임계 경로의 Float = 0

## 비용 관리: 획득가치관리 (EVM)

**EVM(Earned Value Management)**: 범위·일정·비용을 통합해 프로젝트 성과를 측정하는 방법.

### 핵심 지표

| 지표 | 공식 | 의미 |
|------|------|------|
| **PV** | 계획값 | 이 시점에 완료했어야 할 작업의 예산 |
| **EV** | 획득가치 | 실제 완료된 작업의 계획된 가치 |
| **AC** | 실제비용 | 실제 지출 비용 |

### 분산(Variance)과 지수(Index)

| 지표 | 공식 | 해석 |
|------|------|------|
| **CV** | EV - AC | 양수=예산 절감, 음수=예산 초과 |
| **SV** | EV - PV | 양수=일정 앞섬, 음수=일정 지연 |
| **CPI** | EV/AC | 1이상=효율적, 1미만=비효율적 |
| **SPI** | EV/PV | 1이상=앞섬, 1미만=지연 |

**예시**:
```
프로젝트 중간 시점:
PV = 500만원 (이 시점까지 500만원어치 완료 계획)
EV = 400만원 (실제 400만원어치만 완료됨)
AC = 480만원 (실제 480만원 지출)

CV = 400 - 480 = -80 (예산 초과)
SV = 400 - 500 = -100 (일정 지연)
CPI = 400/480 = 0.83 (1달러당 83센트 가치 창출)
SPI = 400/500 = 0.8 (계획 대비 80% 진행)
```

## 핵심 개념 카드

**WBS** ★★★★★
: 범위를 계층적으로 분해한 구조. 일정·비용 추정의 기반. 빠진 작업이 없어야 함.

**임계 경로** ★★★★★
: Float=0인 활동들의 경로 = 프로젝트 최단 기간. 이 경로의 지연이 전체 일정에 직결.

**CPI와 SPI** ★★★★★
: 1 이상=좋음, 1 미만=문제. CPI=비용효율, SPI=일정효율. EVM의 핵심 지표.

## 실전 퀴즈

**Q1. CPI=0.8, SPI=1.2 프로젝트의 현재 상태는?**
> 일정은 앞서 있지만(SPI>1) 예산은 초과 중(CPI&lt;1)입니다. 빨리 진행하고 있지만 더 많은 비용이 들고 있는 상황입니다. PM은 비용 초과 원인을 분석하고 비용 절감 방법을 찾아야 하며, 비용 예측을 업데이트해야 합니다.

**Q2. 범위 크리프를 방지하기 위한 가장 효과적인 방법은?**
> 공식 변경 통제 프로세스(Change Control Process)를 수립하고 모든 범위 변경은 반드시 이 프로세스를 거쳐야 합니다. 명확한 범위 기준선(Scope Baseline) 문서화, 이해관계자 교육(비공식 변경 요청 금지), 정기적인 범위 검토로 방지합니다.
