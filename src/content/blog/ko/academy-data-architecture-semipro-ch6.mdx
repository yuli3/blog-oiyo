## 설계는 운영 조건을 반영합니다

데이터베이스 설계는 논리 모델을 실제 시스템에서 사용할 수 있는 구조로 바꾸는 단계입니다. 테이블, 컬럼, 기본키, 외래키, 인덱스, 제약조건을 정하면서 성능과 정합성의 균형을 잡아야 합니다. DAsP에서는 세부 DBMS 명령보다 설계 의사결정의 이유를 이해하는 것이 중요합니다.

### 설계 요소

| 요소 | 확인 포인트 |
|---|---|
| 기본키 | 행을 유일하게 식별하는가 |
| 외래키 | 관계와 참조 무결성을 지키는가 |
| 인덱스 | 조회 성능을 돕지만 쓰기 비용도 있는가 |
| 제약조건 | 허용되지 않는 값을 막는가 |
| 이력관리 | 변경 사실과 기준 시점을 남기는가 |

좋은 설계는 데이터를 빠르게 조회하는 것만 의미하지 않습니다. 중복이 통제되고, 잘못된 값이 들어오지 않으며, 변경 이력이 필요한 업무에서 추적 가능해야 합니다. 성능만 보고 반정규화를 선택하면 품질 문제가 생길 수 있고, 품질만 보고 모든 구조를 엄격하게 만들면 운영이 어려워질 수 있습니다.

## 데이터 품질

데이터 품질은 정확성, 완전성, 일관성, 유효성, 적시성 같은 기준으로 점검합니다. 품질 관리는 사후 정제만으로 해결되지 않습니다. 입력 단계의 표준, 모델의 제약조건, 운영 절차, 책임 체계가 함께 있어야 합니다. 시험에서는 품질 기준과 발생 가능한 문제 사례를 연결해 두세요.

## 핵심 요약

- 데이터베이스 설계는 논리 모델에 운영 조건을 반영하는 단계입니다.
- 키, 인덱스, 제약조건은 성능과 정합성의 균형을 위해 사용됩니다.
- 데이터 품질은 설계, 표준, 운영 절차가 함께 관리해야 합니다.
