## 제로샷과 퓨샷의 차이

제로샷은 예시 없이 바로 지시하는 방식입니다. “이 글을 세 문장으로 요약해 줘”처럼 작업 설명만 주고 답변을 받습니다. 퓨샷은 원하는 입력과 출력 예시를 몇 개 보여 준 뒤 새 입력을 처리하게 하는 방식입니다.

모델과 기능은 변할 수 있지만, 예시가 답변 기준을 안정시키는 효과는 여전히 중요합니다. 특히 분류, 문체 변환, 규칙 기반 정리처럼 정답 형식이 중요한 작업에서 퓨샷이 유용합니다.

## 언제 제로샷을 쓰나

제로샷은 빠른 초안이나 단순한 변환에 적합합니다. 요구가 명확하고 결과 검토가 쉬울 때 먼저 시도해 볼 수 있습니다.

| 작업 | 제로샷 적합도 | 이유 |
|---|---|---|
| 짧은 요약 | 높음 | 지시만으로도 기준이 비교적 명확함 |
| 아이디어 브레인스토밍 | 높음 | 다양성이 중요하고 정답 형식이 느슨함 |
| 고객 문의 분류 | 중간 | 분류 기준이 애매하면 예시가 필요함 |
| 브랜드 톤 문구 작성 | 낮음 | 원하는 톤을 예시로 보여 주는 편이 안정적임 |

## 퓨샷 예시 만들기

퓨샷 예시는 “입력 -> 출력” 쌍으로 구성하면 이해하기 쉽습니다. 예시가 너무 많을 필요는 없습니다. 서로 다른 경계 사례를 2~4개 정도 주는 것이 입문 단계에서는 충분합니다.

```text
아래 기준에 따라 고객 문의를 분류해 줘.

예시 1
입력: 배송이 언제 오나요?
출력: 배송 문의

예시 2
입력: 결제했는데 영수증이 안 보여요.
출력: 결제 문의

예시 3
입력: 상품이 파손되어 도착했습니다.
출력: 교환·환불 문의

새 입력: 쿠폰을 적용했는데 금액이 그대로예요.
출력:
```

## 좋은 예시의 조건

예시는 단순히 많을수록 좋은 것이 아닙니다. 실제로 자주 나오는 상황, 헷갈리기 쉬운 경계, 원하는 출력 형식을 함께 보여 주어야 합니다. 비슷한 예시만 반복하면 모델이 규칙을 넓게 이해하지 못할 수 있습니다.

| 나쁜 예시 | 좋은 예시 |
|---|---|
| 같은 유형만 여러 개 제시 | 서로 다른 유형과 경계 사례 제시 |
| 출력 형식이 매번 다름 | 출력 형식을 일정하게 유지 |
| 예시에 오류가 있음 | 사람이 검토한 예시 사용 |
| 설명 없이 예시만 나열 | 필요한 경우 짧은 기준 설명 추가 |

## 예시 설계 체크리스트

퓨샷 프롬프트를 만들 때는 먼저 분류 기준이나 결과 형식을 사람이 설명할 수 있어야 합니다. 사람이 기준을 모르면 AI도 안정적으로 따르기 어렵습니다. 예시를 만든 뒤에는 일부러 애매한 입력을 넣어 보고 결과가 기대와 맞는지 확인합니다.

## 핵심 요약

- 제로샷은 예시 없이 지시만 주는 방식이고, 퓨샷은 입력·출력 예시를 함께 주는 방식이다.
- 단순 초안은 제로샷으로 시작해도 되지만, 형식과 기준이 중요한 작업은 퓨샷이 유리하다.
- 좋은 예시는 흔한 사례와 경계 사례를 함께 포함한다.
- 예시 자체가 틀리면 결과도 흔들리므로 예시는 반드시 검토해야 한다.
