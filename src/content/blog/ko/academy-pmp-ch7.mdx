## 의사소통 관리

PM 업무의 90%가 의사소통이라고 합니다. 효과적인 의사소통은 프로젝트 성공의 핵심입니다.

### 의사소통 채널 공식

```
채널 수 = n × (n-1) / 2
```
n = 프로젝트 참여자 수

예: 팀원 5명 → 5×4/2 = **10개 채널**
팀원이 1명 추가되어 6명 → 6×5/2 = **15개 채널**

<Callout type="tip">
**시험 핵심**: 팀 규모가 작을수록 의사소통이 효율적입니다. 새 이해관계자 추가 시 채널 수가 급증하는 이유입니다. 이것이 스크럼이 팀을 3~9명으로 제한하는 이유 중 하나입니다.
</Callout>

### 의사소통 방법

**쌍방향(Interactive)**: 회의, 전화, 화상회의 — 즉각적 피드백 필요 시

**푸시(Push)**: 이메일, 문자, 보고서 — 수신자가 소화할 시간 필요 시

**풀(Pull)**: 포털, 공유 드라이브, 위키 — 정보 접근이 필요 시

## 교훈 (Lessons Learned)

프로젝트에서 배운 것을 문서화해 미래 프로젝트에 활용.

- 프로젝트 **진행 중** 지속적으로 수집 (종료 시만이 아님)
- 긍정적 교훈(잘된 것)과 부정적 교훈(개선 필요) 모두 포함
- 조직 프로세스 자산으로 저장

## 핵심 개념 카드

**채널 수 공식** ★★★★★
: n(n-1)/2. 팀 규모 증가 시 의사소통 복잡도 급증. 소규모 팀 유지의 근거.

**쌍방향 vs 푸시 vs 풀** ★★★★☆
: 상황에 맞는 의사소통 방법 선택. 복잡한 이슈=쌍방향, 정기 업데이트=푸시, 참조 정보=풀.

**교훈** ★★★★☆
: 종료 때만이 아닌 프로젝트 내내 수집. 미래 프로젝트의 조직 자산.

## 실전 퀴즈

**Q1. 프로젝트 팀이 6명에서 10명으로 늘었다. 의사소통 채널은 몇 개나 증가하는가?**
> 6명: 6×5/2 = 15채널. 10명: 10×9/2 = 45채널. 30개 증가. 팀 규모가 67% 늘었는데 채널이 200% 늘어납니다. 이것이 대규모 팀에서 의사소통이 복잡해지는 수학적 이유입니다.

**Q2. 스폰서가 프로젝트 상태를 매주 이메일로 받고 싶다고 한다. 이것은 어떤 의사소통 방법인가?**
> 푸시(Push) 의사소통입니다. 정보를 특정 수신자에게 전달하는 방식으로, 수신자가 능동적으로 찾지 않아도 됩니다. 쌍방향이 아니므로 즉각적인 피드백은 없습니다. 이 경우 이메일 보고서로 충분하며, 긴급 이슈는 별도 회의(쌍방향)로 처리합니다.
