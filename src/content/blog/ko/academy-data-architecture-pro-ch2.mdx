## 전사아키텍처는 전체 설계도입니다

전사아키텍처는 조직의 업무, 데이터, 애플리케이션, 기술 인프라를 같은 방향으로 정렬하는 큰 설계도입니다. DAP에서 데이터아키텍처를 공부할 때 전사아키텍처를 먼저 보는 이유는 데이터가 독립적으로 존재하지 않기 때문입니다. 데이터는 업무가 만들고, 애플리케이션이 사용하며, 기술 환경 위에서 저장되고 이동합니다.

### 네 가지 관점

| 관점 | 확인 질문 |
|---|---|
| 업무 | 어떤 프로세스가 어떤 정보를 필요로 하는가 |
| 데이터 | 핵심 엔터티와 기준 정보는 무엇인가 |
| 애플리케이션 | 어떤 시스템이 데이터를 생성·활용하는가 |
| 기술 | 저장, 연계, 보안, 성능 기반은 무엇인가 |

강의식으로 정리하면, 전사아키텍처는 “업무 목표를 IT 구조로 번역하는 체계”입니다. 데이터아키텍처는 그중에서도 조직이 공통으로 관리해야 할 데이터 자산의 구조, 표준, 흐름을 책임집니다. 따라서 특정 테이블 하나를 잘 설계하는 능력보다, 여러 시스템이 같은 고객·상품·거래 개념을 일관되게 쓰도록 만드는 시야가 중요합니다.

## 학습 포인트

전사아키텍처 문제는 용어 암기보다 관계 파악이 자주 중요합니다. 업무 아키텍처가 데이터 요구를 만들고, 데이터 아키텍처가 애플리케이션과 기술 설계에 기준을 제공한다는 방향을 기억하세요. 또한 아키텍처 원칙은 문서가 아니라 변경 의사결정의 기준입니다.

## 핵심 요약

- 전사아키텍처는 업무, 데이터, 애플리케이션, 기술을 정렬하는 체계입니다.
- 데이터아키텍처는 공통 데이터 자산의 구조와 표준을 책임집니다.
- DAP에서는 개별 설계보다 조직 전체 정합성을 보는 관점이 필요합니다.
