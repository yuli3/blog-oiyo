## ITQ 엑세스 시험 구성

```
ITQ 엑세스(Access) 시험:
→ 실기 시험 45분, 500점 만점
→ A등급 400점 이상 / B등급 300점 이상

출제 영역:
→ DB 구축 (200점): 테이블 2개 작성 및 관계 설정
→ 쿼리 작성 (100점): 조건 쿼리·계산 필드·집계 쿼리
→ 폼 작성 (100점): 폼·하위 폼·컨트롤 작성
→ 보고서 작성 (100점): 그룹화·정렬·계산 보고서

합격 전략:
→ 테이블 구조 먼저 정확하게 설정 (기본키·데이터 형식)
→ 관계 설정 후 쿼리 작업
→ 쿼리 → 폼 → 보고서 순서 작업
→ 저장 경로 및 파일명 반드시 확인

데이터베이스 기본 개념:
→ 데이터베이스: 관련 데이터의 집합·체계적 관리
→ RDBMS: 관계형 데이터베이스 관리 시스템
→ 엑세스: Microsoft Office의 RDBMS 응용 프로그램
→ 주요 개체: 테이블·쿼리·폼·보고서·모듈·매크로
```

## 테이블과 관계 설정

```
테이블 (Table):
→ 데이터를 행(레코드)과 열(필드)로 구성
→ 각 레코드는 하나의 항목·개체 정보

필드 데이터 형식:
→ 짧은 텍스트 (Short Text): 최대 255자 문자
→ 긴 텍스트 (Long Text): 메모·설명 (구 메모)
→ 숫자 (Number): 정수·실수 계산용
→ 날짜/시간 (Date/Time)
→ 통화 (Currency): 소수점 4자리 고정
→ 예/아니요 (Yes/No): Boolean
→ OLE 개체: 이미지·파일 첨부
→ 일련 번호 (AutoNumber): 자동 증가 정수 → 기본키 권장

필드 속성:
→ 필드 크기: 텍스트(50자 기본)·숫자 형식
→ 유효성 검사 규칙: 입력 데이터 제한
→ 필수 입력: 빈 값 금지
→ 기본값: 새 레코드 기본 입력값
→ 인덱스: 중복 허용 / 중복 불허

기본키 (Primary Key):
→ 레코드를 고유하게 식별하는 필드
→ NULL 불가·중복 불가
→ 설정: 필드 선택 → 디자인 탭 → 기본 키

관계 설정:
→ 데이터베이스 도구 탭 → 관계
→ 일대다 관계 (1:N): 가장 일반적
  예: 학생(1) - 성적(N)
→ 일대일 관계 (1:1): 정보 분리
→ 다대다 관계 (M:N): 중간 테이블 필요
→ 참조 무결성: 부모 없는 자식 레코드 방지

조인 유형:
→ 내부 조인 (Inner Join): 양쪽 모두 있는 데이터만
→ 왼쪽 외부 조인: 왼쪽 테이블 전체 + 오른쪽 일치
→ 오른쪽 외부 조인: 오른쪽 전체 + 왼쪽 일치
```

## 쿼리 작성

```
쿼리 (Query):
→ 데이터 검색·추출·계산·업데이트

쿼리 종류:
→ 선택 쿼리 (Select Query): 데이터 검색·표시 (가장 기본)
→ 업데이트 쿼리 (Update Query): 레코드 일괄 수정
→ 추가 쿼리 (Append Query): 다른 테이블에 레코드 추가
→ 삭제 쿼리 (Delete Query): 조건에 맞는 레코드 삭제
→ 크로스탭 쿼리 (Crosstab Query): 행·열 요약 (엑셀 피벗과 유사)
→ 매개 변수 쿼리 (Parameter Query): 실행 시 조건 입력

쿼리 디자인 뷰 구성:
→ 필드: 표시할 필드 선택
→ 테이블: 필드 원본 테이블
→ 정렬: 오름차순·내림차순
→ 표시: 체크 시 결과에 표시
→ 조건: WHERE 절에 해당

조건 입력 방법:
→ 같음: 값 직접 입력 (예: "서울")
→ 비교: >, >=, <, <=, <> (같지 않음)
→ 범위: Between 10 And 20
→ 목록: In ("서울", "부산", "인천")
→ 패턴: Like "김*" (김으로 시작)
→ NULL 확인: Is Null / Is Not Null
→ 날짜: #2026-01-01# 형식 (샵으로 감쌈)

계산 필드 (Calculated Field):
→ 필드 행에 새 이름: 수식 형식
→ 예: 합계: [단가] * [수량]
→ 문자열 연결: [성] & " " & [이름]
→ 날짜 함수: Year([날짜]), DateDiff("d", [시작일], [종료일])
→ IIf(조건, 참값, 거짓값): 조건부 값

집계 쿼리:
→ 쿼리 디자인 탭 → 합계 (Σ) 클릭 → 합계 행 추가
→ 집계 함수: Sum·Avg·Max·Min·Count·StDev
→ 그룹화 (Group By): 분류 기준 필드
→ 조건 (Where): 집계 전 조건 필터
```

## 폼과 보고서

```
폼 (Form):
→ 데이터 입력·표시·편집을 위한 사용자 인터페이스

폼 만들기 방법:
→ 자동 폼: 폼 마법사·빠른 폼
→ 디자인 뷰: 직접 디자인

폼 구역:
→ 폼 머리글: 제목·로고 (한 번만 표시)
→ 페이지 머리글: 각 페이지 상단
→ 본문: 데이터 반복 표시
→ 페이지 바닥글·폼 바닥글

컨트롤 유형:
→ 텍스트 상자: 데이터 입력·표시
→ 레이블: 설명 텍스트
→ 콤보 상자: 드롭다운 목록 선택
→ 목록 상자: 목록에서 선택
→ 확인란·옵션 단추: 예/아니요 선택
→ 명령 단추: 매크로·코드 실행

하위 폼 (Subform):
→ 기본 폼 안에 다른 폼 삽입
→ 1:N 관계 데이터 함께 표시
→ 연결 필드: 기본 폼 - 하위 폼 연결

보고서 (Report):
→ 데이터 인쇄·출력용 개체

보고서 그룹화·정렬:
→ 보고서 마법사 또는 디자인 뷰
→ 그룹화: 특정 필드 값이 같은 레코드 묶음
→ 그룹 머리글·바닥글: 그룹별 제목·합계
→ 정렬: 그룹 내 레코드 정렬 순서

보고서 계산 컨트롤:
→ 텍스트 상자에 수식 입력
→ 합계: =Sum([금액])
→ 평균: =Avg([점수])
→ 페이지 번호: =[Page] & "/" & [Pages]
→ 현재 날짜: =Now() 또는 =Date()
```

## ITQ 인터넷 활용

```
ITQ 인터넷 시험 구성:
→ 실기 45분, 500점 만점
→ 인터넷 검색·메일·웹 문서 작성

인터넷 기본 개념:
→ 인터넷: 전 세계 컴퓨터 네트워크의 네트워크
→ WWW (World Wide Web): 하이퍼텍스트 기반 정보 시스템
→ IP 주소: 네트워크 기기 식별 주소 (IPv4: 32비트·IPv6: 128비트)
→ 도메인 (Domain): IP 주소의 문자 형식
  예: www.naver.com
→ DNS (Domain Name System): 도메인 → IP 변환 서버

URL 구조:
→ http://www.example.com:80/path?query=value#fragment
  프로토콜://호스트명:포트/경로?쿼리#앵커

주요 프로토콜:
→ HTTP (80포트): 웹 문서 전송
→ HTTPS (443포트): 암호화 웹 전송 (SSL/TLS)
→ FTP (21포트): 파일 전송
→ SMTP (25포트): 이메일 발송
→ POP3 (110포트): 이메일 수신 (서버에서 삭제)
→ IMAP (143포트): 이메일 수신 (서버 유지)
→ DNS (53포트): 도메인 이름 해석

검색 연산자:
→ AND 검색: 두 단어 모두 포함 (기본값, 띄어쓰기)
→ OR 검색: 어느 하나 포함
→ 제외 검색: - 기호 (예: 사과 -apple)
→ 정확한 구문: 따옴표 "검색어"
→ 사이트 검색: site:naver.com
→ 파일 형식: filetype:pdf

인터넷 보안:
→ 피싱 (Phishing): 가짜 사이트로 개인정보 탈취
→ 파밍 (Pharming): DNS 조작으로 진짜처럼 보이는 가짜 사이트
→ 스니핑 (Sniffing): 네트워크 패킷 도청
→ 방화벽 (Firewall): 내부·외부 트래픽 제어
→ 공인 인증서: 전자 서명·본인 인증
```

## 자주 묻는 질문

**Q. 엑세스 쿼리에서 조건을 같은 행에 쓸 때와 다른 행에 쓸 때의 차이는 무엇인가요?**
A. 쿼리 디자인 뷰에서 조건 입력 방법에 따라 AND와 OR 연산자가 적용됩니다. 같은 조건 행에 여러 필드에 조건을 입력하면 AND 연산이 됩니다. 두 조건을 모두 만족하는 레코드만 결과에 포함됩니다. 예를 들어 부서 필드에 "영업"이라고 조건을 입력하고 같은 행의 급여 필드에 ">300"이라고 입력하면 영업부이면서 급여가 300 초과인 레코드만 추출됩니다. 반면 다른 조건 행(또는 행)에 조건을 각각 입력하면 OR 연산이 됩니다. 부서 행에 첫 번째 조건 행에 "영업", 두 번째 조건 행에 "인사"라고 입력하면 영업부이거나 인사부인 레코드를 모두 추출합니다.

**Q. ITQ 인터넷 시험에서 웹 문서 작성 시 자주 감점되는 부분은 무엇인가요?**
A. ITQ 인터넷 시험의 웹 문서 작성(HTML 편집기 또는 메모장 활용)에서 자주 실수하는 부분들이 있습니다. 첫째, 태그 오타나 대소문자 오류입니다. HTML은 대소문자를 구분하지 않지만 속성값은 따옴표로 정확히 감싸야 합니다. 둘째, 이미지·링크 경로 오류입니다. 상대 경로와 절대 경로를 혼동하거나 파일명이 틀리면 이미지가 표시되지 않습니다. 셋째, 테이블 구조 오류입니다. tr, td, th 태그의 구조가 맞지 않으면 표 레이아웃이 틀어집니다. 넷째, 글꼴 색·크기·정렬 등 스타일 설정을 빠뜨리는 경우가 많습니다. 다섯째, 저장 시 파일 형식(HTML)과 인코딩(UTF-8)이 지시 사항과 다른 경우도 감점됩니다. 시험 전 HTML 기본 태그와 속성을 암기하고 실습해 두는 것이 중요합니다.
